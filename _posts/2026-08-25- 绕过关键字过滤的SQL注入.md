# DASCTF SQL 注入 WriteUp



## 一、题目描述与分析

- **页面表现**：页面有一个输入框用于查询数据。提交正常数据 `1` 时，返回数组结果；提交特殊字符时，会暴露出后端的报错信息。

## 二、漏洞探测与过滤分析

### 注入点确认

在输入框输入 `1'`，页面报错 `error 1064`，说明存在**单引号闭合的 SQL 注入点**。

### 获取过滤规则

通过构造特定的 Payload 触发后端回显（或查看源码），获取到后端的核心过滤代码：

```php
return preg_match("/select|update|delete|drop|insert|where|\./i",  $ inject);

###过滤条件分析
代码使用正则表达式对输入内容进行了严格的黑名单过滤，禁止了以下关键字：
select, update, delete, drop, insert
where
. (句号)
这意味着常规的联合注入（UNION SELECT）和基于 information_schema 的手动盲注（需要用到 where 和 .）都将失效。
三、破局思路与攻击链
面对严格的关键字过滤，破局点在于 堆叠注入（Stacked Injection） 配合 MySQL 预处理语句（Prepared Statements）。
堆叠注入：虽然常规查询被堵，但可以利用分号 ; 执行多条 SQL 语句。
绕过 Select 过滤：select 被过滤了，不能直接写。但可以利用 CONCAT() 函数将字符串拼接（如 'sel' 和 'ect'），在内存中组合成完整的 SQL 语句。
预处理执行：利用 MySQL 的 PREPARE 和 EXECUTE 语句，将拼接好的字符串当作 SQL 命令执行。
四、解题步骤
第一步：探测表结构
由于无法使用 UNION SELECT，利用堆叠注入执行 SHOW TABLES 来查看数据库中的表。
Payload：
sql



'; show tables;#
结果：
页面返回两个表名：
words
（一个纯数字命名的表，非常可疑）
第二步：探测可疑表字段
查看数字表 1919810931114514 中是否有 flag 字段。注意：纯数字表名必须使用反引号 包裹。
Payload：
sql



'; show columns from `1919810931114514`;#
结果：
页面返回该表的字段结构，发现包含字段 flag。
第三步：构造绕过 Payload 获取 Flag
目标明确：从表 1919810931114514 中查询字段 flag。由于 select 被过滤，使用预处理语句绕过。
Payload：
sql



';SET @sql=CONCAT('sel','ect flag from `1919810931114514`');PREPARE stmt FROM @sql;EXECUTE stmt;#
原理拆解：
表格
下载为表格
导出为图片
部分	作用
';	闭合前面的单引号并结束原语句
SET @sql=CONCAT(...)	将 select 拆分为 'sel' 和 'ect' 拼接，绕过正则检测
PREPARE stmt FROM @sql;	准备执行该 SQL 字符串
EXECUTE stmt;	真正执行查询
五、最终结果
提交上述 Payload 后，页面返回包含 Flag 的数组，成功获取 Flag。
六、知识点总结
堆叠注入：利用 ; 分隔多条 SQL 语句依次执行
MySQL 预处理语句：PREPARE + EXECUTE 可以执行动态拼接的 SQL
CONCAT 绕过黑名单：将敏感关键字拆分后拼接，绕过正则匹配
反引号包裹特殊表名：纯数字表名需用反引号 包裹才能被 MySQL 正确识别
